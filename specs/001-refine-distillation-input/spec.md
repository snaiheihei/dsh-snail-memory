# Feature Specification: 提升自动蒸馏与整合的记忆质量

**Feature Branch**: `001-refine-distillation-input`

**Created**: 2026-11-11

**Status**: Draft

**Input**: User description: "插件蒸馏用户内容范围精简，提升历史记忆质量"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 只沉淀具有持久价值的会话证据 (Priority: P1)

作为使用分层记忆的插件用户，我希望自动蒸馏过滤普通中间输出、一次性请求和临时过程噪声，同时保留我的关注与困惑、工具失败与修复经验、模型走过的弯路与纠正、关键决策以及可复用的长任务流程，而不是只保留我的原话。

**Why this priority**: 普通助手和工具输出会稀释历史记忆，但失败、修复和纠正等高价值证据也常只存在于助手或工具事件中；仅按来源筛选会同时丢掉噪声与经验。

**Independent Test**: 使用一组标注了证据来源和持久价值的混合对话样本触发自动蒸馏，核对低价值候选被阻挡，高价值证据不会仅因来自助手或工具而被排除，且保留下来的记忆可追溯到原始证据。

**Acceptance Scenarios**:

1. **Given** 对话包含常规工具中间结果、普通模型中间输出、临时进度以及问天气、识别文字等一次性请求，**When** 系统执行自动蒸馏，**Then** 这些低价值内容被判定为 `drop`，不生成新的历史记忆。
2. **Given** 对话包含用户关注或困惑、工具失败与修复、模型弯路与纠正、关键决策或可复用长任务流程，**When** 这些证据位于用户、助手或普通工具事件中，**Then** 系统均将其纳入质量评估，不因来源而直接排除，并将具有持久价值的候选判定为 `keep`。
3. **Given** 一次性请求或常规工具过程中包含有复用价值的失败原因、修复方法或明确决策，**When** 系统评估该段证据，**Then** 不按请求主题整体丢弃，而只阻挡普通过程内容并保留其中的持久经验。
4. **Given** 待处理内容包含插件生成的记忆快照、记忆读取或反馈结果，**When** 系统构造蒸馏证据，**Then** 这些内容继续被排除，避免把旧记忆反复蒸馏成新记忆。

---

### User Story 2 - 在正常整合中清理低价值历史记忆 (Priority: P2)

作为已经积累历史记忆的用户，我希望正常整合能对一组待复核的 dirty 记忆执行 `keep`、`supersede` 或 `forget` 评审，清理低价值、重复、陈旧或已被纠正的内容，同时确保我显式记住或纠正的记忆不会被自动遗忘。

**Why this priority**: 只改善新增记忆无法处理已经积累的低价值或失效内容；受约束的整合评审可以持续改善历史质量，同时避免模型任意删除用户数据。

**Independent Test**: 构造包含普通、重复、陈旧、冲突和显式维护记忆的 dirty 集，在正常整合中逐项核对裁决、实际变更、作用域隔离和遗忘审计记录。

**Acceptance Scenarios**:

1. **Given** dirty 集中存在仍有价值、已被更好记忆取代以及不再值得保留的条目，**When** 系统执行整合评审，**Then** 每条记忆分别得到 `keep`、`supersede` 或 `forget` 裁决，只有符合执行条件的裁决才改变存储内容。
2. **Given** 模型建议遗忘一条不在本次 dirty 集、超出当前作用域、缺少有效依据或受用户显式保护的记忆，**When** 系统处理该建议，**Then** 系统拒绝自动遗忘并保持原记忆不变。
3. **Given** 一条记忆被合法遗忘，**When** 用户检查整合结果，**Then** 可以找到遗忘原因和来源证据，且审计信息不复制被删除记忆全文或秘密。
4. **Given** 不同记忆层或工作区中存在相似、重复或陈旧条目，**When** 系统执行整合，**Then** 不跨越既有作用域边界遗忘或替换记忆。

---

### User Story 3 - 保持主动维护与升级行为可预期 (Priority: P2)

作为现有插件用户，我希望本次质量治理不改变主动记住、纠正、读取、记忆层选择或快照访问方式，也不在升级时自动批量清理历史数据。

**Why this priority**: 自动质量裁决不能破坏用户主动维护记忆的既有路径，历史治理应仅发生在正常整合的明确复核范围内。

**Independent Test**: 分别执行主动记住、纠正、详情读取、分层选择和快照访问，并在启用新规则时核对既有记忆不会因升级本身被批量改写或删除。

**Acceptance Scenarios**:

1. **Given** 用户通过既有入口主动记住或纠正一条记忆，**When** 新质量规则生效，**Then** 主动维护行为保持不变，且该条目受到自动遗忘保护。
2. **Given** 数据中已经存在历史记忆，**When** 用户启用本次变更但未发生正常 dirty 整合，**Then** 系统不会仅因升级批量重写或删除这些记忆。

---

### Edge Cases

- 对话只有普通助手输出、常规工具结果或临时进度时，不产生新的记忆候选。
- 同一段证据同时包含普通过程内容和失败修复经验时，只保留具有持久价值的部分。
- 天气、文字识别等主题本身不是绝对过滤条件；其中出现可复用经验、稳定偏好或关键决策时仍应评估。
- “关联度低”指持久项目价值低，而不是与当前话题的文本相似度低；不得仅因话题不同遗忘有效记忆。
- 用户消息为空、只含空白或没有持久价值时，不生成记忆候选。
- 高价值证据跨越处理批次时，不得因过滤、分批或重试而遗漏或重复处理。
- dirty 集为空或所有条目均为 `keep` 时，不改变既有记忆。
- `supersede` 的替代关系不明确、跨越作用域或指向不存在条目时，不执行替换。
- 显式记住或纠正的记忆进入 dirty 集时，可以评审和保留，但不得由自动 `forget` 删除。
- 遗忘建议缺少原因、来源证据或目标状态已变化时，不执行删除。
- 没有符合条件的新证据时，既有记忆保持不变；升级本身不触发历史数据批量清理。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: System MUST 依据持久价值而非消息来源单独决定蒸馏资格，允许真实用户、助手和普通工具事件中的有效证据进入同一质量评估。
- **FR-002**: System MUST 阻挡常规工具中间结果、普通模型中间输出、临时任务状态以及问天气、识别文字等一次性请求中的低价值内容，不得将其沉淀为历史记忆。
- **FR-003**: System MUST 保留并评估用户关注与困惑、工具失败与修复、模型弯路与纠正、关键决策及可复用长任务流程的证据，即使这些证据只出现在助手或工具事件中。
- **FR-004**: System MUST 在自动蒸馏中要求模型对每个记忆候选给出 `keep` 或 `drop` 质量判定，只有 `keep` 候选可以进入后续写入流程。
- **FR-005**: System MUST 允许按证据内容而非请求主题作质量判断；一次性请求中的可复用失败经验、修复方法、稳定偏好或关键决策不得被主题过滤误删。
- **FR-006**: System MUST 继续排除插件生成的记忆快照、记忆读取和记忆反馈结果，避免递归蒸馏旧记忆或把注入内容误认为新证据。
- **FR-007**: System MUST 保持有效证据的原始顺序与可追溯来源，并确保跨批次处理时无遗漏、无重复。
- **FR-008**: 当待处理范围内没有具有持久价值的新证据时，System MUST NOT 生成新的记忆或改写既有记忆。
- **FR-009**: System MUST 在正常整合过程中将待质量复核的 dirty 记忆集交给模型评审，并提供重复、陈旧、冲突和低持久价值等 dirty filter 作为判断依据。
- **FR-010**: System MUST 要求模型对 dirty 集中的每条记忆给出 `keep`、`supersede` 或 `forget` 裁决；其中“低关联”必须表示持久项目价值低，不得表示与当前话题的相似度低。
- **FR-011**: System MUST 将模型给出的 `forget` 视为建议，仅在确定性规则确认目标属于本次 dirty 集、作用域一致、未受保护且原因与来源证据有效时执行遗忘；否则保持原记忆不变。
- **FR-012**: System MUST 仅在替代关系明确、目标与替代记忆均有效且作用域一致时执行 `supersede`，不得借替换删除无关记忆。
- **FR-013**: System MUST 保护用户显式记住或纠正的记忆，不得因自动 `forget` 裁决将其删除；用户主动删除或纠正的既有入口不受影响。
- **FR-014**: System MUST 为每次实际遗忘记录原因和来源证据，且审计记录不得复制被删除记忆全文或秘密。
- **FR-015**: System MUST 保持既有记忆作用域隔离，不得跨工作区或记忆层自动遗忘、替换或合并记忆。
- **FR-016**: System MUST NOT 因本次变更加载、批量重写或删除既有历史记忆；历史清退只能发生在正常整合的 dirty 复核范围内。
- **FR-017**: System MUST 保持主动记住、主动纠正、详情读取、记忆层选择和快照注入的既有行为不变。
- **FR-018**: System MUST 对保留证据、模型候选及整合裁决继续执行既有秘密扫描、长度限制和安全检查，不得因引入质量门而降低安全约束。

### Key Entities

- **蒸馏证据**: 自动蒸馏可评估的原始会话内容，可来自真实用户、助手或普通工具事件，并保留原始顺序与来源引用。
- **蒸馏质量裁决**: 模型对记忆候选作出的 `keep` 或 `drop` 判断，决定候选能否进入写入流程。
- **Dirty 记忆集**: 正常整合中因可能重复、陈旧、冲突或低持久价值而需要复核的既有记忆集合，不等同于全部历史记忆。
- **整合裁决**: 模型对 dirty 记忆作出的 `keep`、`supersede` 或 `forget` 建议；实际变更还须通过系统规则核验。
- **受保护记忆**: 用户显式记住或纠正的记忆，不受自动遗忘影响。
- **遗忘审计记录**: 实际遗忘发生后保留的原因与来源证据，用于解释和检查变更，不保存被删除记忆全文。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 在标注为普通中间输出、一次性请求或临时过程噪声的验收样本中，100% 的低价值候选被 `drop`，产生的新历史记忆为 0 条。
- **SC-002**: 在覆盖关注与困惑、失败与修复、弯路与纠正、关键决策和可复用流程的标注样本中，100% 的高价值证据不会仅因来自助手或工具而被排除，并形成可追溯的 `keep` 候选。
- **SC-003**: 在需要多个处理批次的长对话验收样本中，100% 的有效证据按原顺序被处理且恰好一次，无遗漏或重复。
- **SC-004**: 在 dirty 整合验收样本中，100% 的条目得到三种整合裁决之一；受保护、越界或不符合执行条件的记忆被自动删除数为 0 条。
- **SC-005**: 所有实际发生的自动遗忘中，100% 具有原因和来源证据记录，跨作用域自动变更为 0 条。
- **SC-006**: 既有主动记住、纠正、读取、记忆层选择和快照访问的验收用例 100% 保持通过，且升级本身造成的既有记忆自动变更为 0 条。

## Assumptions

- 本次采用两道质量门：蒸馏阶段以 `keep/drop` 阻挡低价值新增候选，正常整合阶段以 `keep/supersede/forget` 复核 dirty 记忆。
- 蒸馏输入不是“只保留真实用户消息”；助手与工具事件中的失败、修复、弯路、纠正、决策和流程证据具有保留价值。
- 天气、文字识别等一次性请求默认属于低价值内容，但主题不是绝对排除条件，其中可复用的经验或明确决策仍需评估。
- 模型负责语义质量判断，实际遗忘由确定性规则约束；显式记住或纠正的记忆受到自动遗忘保护。
- 既有历史记忆只在正常 dirty 整合中逐步复核，不在升级时自动批量清理。
- 验收质量结论基于覆盖上述证据类型和噪声类型的人工标注代表性样本，而不是仅凭历史记忆数量判断效果。

## 不在范围内 (Out of Scope)

| 不做的事 | 为什么不做 | 以后会不会做 |
|---|---|---|
| 将自动蒸馏简化为只保留真实用户消息 | 会丢失只存在于助手或工具事件中的失败、修复和纠正证据 | 不采用该方向 |
| 升级时批量重写、清理或删除全部既有历史记忆 | 历史治理必须限制在正常 dirty 整合范围内，避免不可预期变更 | 如需一次性治理，另立变更并由用户确认 |
| 自动遗忘用户显式记住或纠正的记忆 | 用户主动维护的意图优先于模型质量建议 | 仅通过用户主动操作处理 |
| 修改记忆分层、快照注入、详情读取或主动记住/纠正流程 | 这些流程不是本次质量治理的目标 | 仅在独立需求中处理 |
| 引入新的语义排序、向量检索或记忆召回机制 | 本次关注蒸馏与整合质量，不改变检索与排序设计 | 暂不在本变更考虑 |
| 允许模型绕过作用域、保护或审计规则直接删除记忆 | 语义建议不能替代确定性的数据安全约束 | 不纳入自动整合能力 |
